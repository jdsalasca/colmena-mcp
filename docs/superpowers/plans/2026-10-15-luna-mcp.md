# codex-mcp-juanda (luna-mcp) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MCP server (stdio) that lets Claude orchestrate `gpt-6-luna`/`max` agents through `codex exec`, with isolation, resume, summarize/compact/handoff and token-light output.

**Architecture:** Thin MCP tool layer over `JobManager` (queue + lifecycle + disk state), `runner` (spawn/parse `codex exec --json`), `isolation` (git worktree), `report` (compact reporting). No DB; state in `~/.luna-mcp/`.

**Tech Stack:** Node 24 ESM (no build), `@modelcontextprotocol/sdk`, `zod`, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-15-luna-mcp-design.md`

## Global Constraints

- Model fixed: `-m gpt-6-luna -c model_reasoning_effort="max"`; never overridable by tool params.
- Global flag `--search` goes BEFORE `exec`. Spawn with stdin closed (`stdio: ['ignore', 'pipe', 'pipe']`) or codex waits for input.
- Verified JSONL events: `{"type":"thread.started","thread_id"}`, `item.completed` with `item.type=="agent_message"` and `item.text`, `turn.completed` with `usage`.
- Codex binary: `LUNA_CODEX_BIN` else newest-by-mtime `codex.exe` under `%LOCALAPPDATA%\OpenAI\Codex\bin` (the old `bin\codex.exe` 0.130 rejects `max`). A `.js` path runs via `process.execPath` (used by tests).
- Env: `LUNA_HOME` (default `~/.luna-mcp`), `LUNA_MAX_PARALLEL` (4), `LUNA_JOB_TIMEOUT_MIN` (60).
- Tool outputs are compact JSON; heavy data goes to disk and a path is returned. `luna_wait` timeout default 120s, max 600s.
- Windows: kill trees with `taskkill /PID <pid> /T /F`.
- `luna_merge`/`luna_cleanup` only touch `luna/*` branches and worktrees under `LUNA_HOME/worktrees`.

## Review Focus

- Task text with quotes/newlines/`$`/backticks must reach codex intact (passed as argv, never via shell).
- `cwd` with spaces or non-ASCII (`Documents\Programming-personal`, `investigación`).
- Worktree requested outside a git repo → clear error, no half-created state.
- Two parallel jobs touching the same file never collide (separate worktrees).
- `luna_merge` with dirty target tree or conflicts → refuses/reports, leaves repo clean.
- Agent reply missing RESULT/FILES/TESTS/RISKS → truncated raw message returned, not a crash.
- Server restart with a `running` job whose process is gone → `orphaned`.
